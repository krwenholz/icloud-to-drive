# Drive Mirror

A personal macOS 14+ menu bar app that mirrors Markdown folders from iCloud Drive into Google Drive, converting each `.md` file into a Google Doc. Your notes become searchable and readable through Claude's Google Drive connector.

Sync is strictly one-way. iCloud is the source of truth. Drive holds a derived, disposable copy under a top-level `iCloud Mirror` folder, with one subfolder per root. Nothing flows back.

- It reconciles fully on launch, on wake, on a timer (hourly by default; see Settings → General), and when files change (debounced). Sync Now in the menu runs one on demand.
- Each root folder gets a `_sync-status` Doc with the last successful sync time, how long it took and on which Mac, what it created, updated, moved, and trashed, the mirrored-file count, the file format and update strategy, any failing files (with the date each started failing), and any deletions on hold.
- It requests only the `drive.file` scope, so the app can see only files it created.
- It never permanently deletes. It only trashes.

## How it works

The `MirrorCore` package holds all the logic and is tested with `swift test`. The app is a thin SwiftUI layer whose Xcode project is generated by XcodeGen. `mirrorctl` is a CLI over the same code. There are no third-party dependencies.

The app and `mirrorctl` share one Application Support directory, `~/Library/Application Support/Drive Mirror/`:

- `config.json`
- `state.json`
- `drive-mirror.log`
- `google-client.json`

They also share one Keychain item (service `dev.krw.DriveMirror`, account `google-refresh-token`). Sign in once with either and both are signed in.

## Building

1. `mise install` pins `xcodegen` and `actionlint`.
2. `/usr/bin/make check` runs lint, `swift test`, and the app build. It builds unsigned if no team is set.
3. `/usr/bin/make format` formats the Swift sources in place.
4. `mise exec -- xcodegen generate` creates `DriveMirror.xcodeproj` (generated, gitignored). Open it in Xcode.

To sign builds, copy `Config/Local.xcconfig.example` to `Config/Local.xcconfig` and set `DEVELOPMENT_TEAM`.

Run the CLI from the repo root:

```
swift run --package-path Packages/MirrorCore mirrorctl <command>
```

| Command | What it does |
|---|---|
| `auth` | Sign in to Google (shared with the app) |
| `probe` | Check Drive behavior live and print a PASS/FAIL table |
| `sync <path> [--dry-run]` | Reconcile a folder; `--dry-run` only prints the plan |
| `rebuild-state [<path>]` | Rebuild local state from Drive, for one folder or every root |
| `help` | Show usage |

A `<path>` that matches a root in the app's config uses that root and the app's state. Any other folder is synced as a temporary root with its own state file.

Live tests use your real Google account and are off by default:

```
LIVE_DRIVE=1 swift test --package-path Packages/MirrorCore
```

Golden request fixtures regenerate with `UPDATE_GOLDEN=1`.

## Hand-off checklist

These are the manual steps, in order.

### Google Cloud setup (about 10 minutes)

1. Create a Google Cloud project and enable the Google Drive API.
2. Configure the OAuth consent screen as External, with yourself as the contact, and add only the `drive.file` scope.
3. Set the publishing status to "In production." This step matters. While the status is "Testing," Google expires refresh tokens after 7 days, and you would have to sign in again every week. `drive.file` is not a restricted scope, so personal use should not require Google's verification process. At most, you will click past an "unverified app" warning when signing in.
4. Create an OAuth client of type "Desktop app," download its JSON file, and save it as `~/Library/Application Support/Drive Mirror/google-client.json`. You can also use Settings → Account → Import client file…

### Mac setup

5. Make sure Xcode is signed in to your Apple ID so it can sign builds with a free personal development team. Put that team ID in `Config/Local.xcconfig`. Signing with a stable identity keeps macOS from asking for Keychain and folder permissions again after every rebuild.
6. Run `sudo pmset -c sleep 0` to disable system sleep. Display sleep is unaffected.
7. In Finder, right-click each folder you plan to mirror and choose "Keep Downloaded."

### First live run

8. Run `mirrorctl auth` and complete sign-in in the browser.
9. Run `mirrorctl probe` and paste the full output back to Claude Code. Claude Code then confirms or switches the default update strategy and fixes any failures before you go further.
10. Run `mirrorctl sync <one of your folders> --dry-run` and check that the plan looks right.

### App

11. Build and launch the app, add your folders in Settings, and turn on launch at login.
12. Confirm that the Docs and the `_sync-status` Doc appear in Google Drive under `iCloud Mirror`.
13. In a Claude chat with the Google Drive connector enabled, ask Claude to find a phrase from one of your notes and confirm it finds and reads the right Doc.

## Using the app

The app lives in the menu bar and has no Dock icon. The icon shows one of four states: idle (`checkmark.icloud`), syncing, error, or paused.

Menu items:

- Last sync time, shown as a relative time
- One line per root, with its status or error. When the mass-deletion guard is holding deletions, the line names the first few files and counts the rest.
- Sync Now
- Pause / Resume
- Apply pending deletions (shown only when the mass-deletion guard is holding deletions)
- Open in Google Drive
- Settings…
- Copy Diagnostics
- Quit

Settings has three tabs:

- **Account**: sign in or out, see the signed-in email, and Import client file…
- **Folders**: add a folder with the folder picker (the display name defaults to the folder name), or remove one. Removing asks whether to also trash the Drive folder. Display names must be unique across folders, ignoring case. Renaming a folder renames its Drive folder too, keeping the same folder and Doc links. "Convert to Google Docs" is on by default; turn it off to upload plain `.md` files that keep their extension. Changing it re-creates every file in that folder in the new format and trashes the old copies, and the `_sync-status` Doc stays a Doc either way. You can edit the include and exclude patterns, one per line. Defaults include `**/*.md` and exclude `.trash/` and `.obsidian/`. Hidden files and folders are always excluded. Patterns support `*`, `**`, and `?`, and match case-insensitively.
- **General**: launch at login, the name of the top-level Drive folder (empty means `iCloud Mirror`; changing it renames the existing folder), how often the full pass runs (15 minutes, 1 hour, or 6 hours; changes to files still sync within seconds), and the update strategy, In place or Replace.

### Notifications

The app asks for permission to show alerts at launch and sends one when a problem first appears: a folder with failing files (one notification per folder, not per file), deletions put on hold, an expired Google sign-in, or a folder it can't reach. It doesn't repeat a notification until the problem has cleared and come back, and it never notifies about successful syncs. If you decline the permission, the menu bar icon and menu still show every problem.

### Errors that don't go away

A file that has been failing for more than 30 days and hasn't changed since stops being retried, and disappears from the menu count and the `_sync-status` Doc. Editing the file retries it, and so does Sync Now.

### If you trash the Drive folders

If you trash a root's folder, or the top-level folder, in Drive, the next sync notices and recreates the tree from your local files. The old copies stay in Drive's trash.

## Troubleshooting

### Sign-in expires every 7 days

Cause: the OAuth consent screen is still in "Testing." Fix: switch the publishing status to "In production," then sign in again.

### macOS keeps asking for Keychain or folder permissions after each rebuild

Cause: the build is not signed with a stable development identity. Fix: set `DEVELOPMENT_TEAM` in `Config/Local.xcconfig` and rebuild.

### Files stay "not downloaded"

The `_sync-status` Doc shows "Waiting for iCloud to download." The app asks iCloud to download those files and retries on the next pass.

1. Turn on Keep Downloaded for the folder in Finder.
2. Check iCloud Drive storage and sync status in System Settings.

`brctl` can give more detail about iCloud sync, but you should not need it.

### The mass-deletion guard fired

The guard trips when a reconcile would trash more than 25% of a root's mirrored Docs and more than 10 Docs. It holds the trashes, marks the root as needing attention, and lists it in the status Doc.

The usual cause is a folder that is temporarily unavailable or iCloud misbehaving. Check the folder in Finder. If the deletions are real, choose Apply pending deletions from the menu. A missing or unreadable root never trashes anything.

### Rebuilding state

Quit the app first. Then do either of these:

- Run `mirrorctl rebuild-state` for every configured root, or `mirrorctl rebuild-state <path>` for one.
- Delete `~/Library/Application Support/Drive Mirror/state.json` and relaunch.

State is recovered from the Docs' `appProperties` and descriptions. This creates no duplicates. Unchanged files are hashed once but not re-uploaded. A corrupt state file is set aside as `state.json.corrupt`.

### Logs

- `~/Library/Application Support/Drive Mirror/drive-mirror.log` is size-capped and rolls to `drive-mirror.log.1`.
- Console.app shows the same events under subsystem `dev.krw.DriveMirror`.
- Copy Diagnostics in the menu puts a report on the clipboard.
